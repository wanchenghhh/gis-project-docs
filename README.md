# GIS 项目文档编写与检查助手

将 GIS 项目的资料整理为实施方案或研制工作总结，并检查指标、成果、前后一致性与引用。

**陪你的项目，从蓝图走向交付。**

让计划有据、过程可循、成果可验，以项目文档为每一步提供支撑。

**当前版本：融合版（v0.3.0）。目前支持实施方案与工作总结，更多项目文档敬请期待。** 不同素材的经验已合并为一套通用章节指南，按项目范围组织内容。

## 使用

将 `skills/gis-project-docs` 文件夹复制到个人技能目录 `~/.agents/skills/`，然后调用：

> 请使用 $gis-project-docs，根据附件项目资料编写实施方案，先给出建议目录和各章要点。

其他调用示例：

- 检查总结：重点检查指标结论、成果清单、前后一致性和失效引用，输出位置、依据与建议，暂不修改原文。
- 深化方案：完善业务流程、数据流程、接口及子系统输入输出，保持实施方案深度。
- 对照检查：核对实施方案与总结报告中的要求、计划、实际结果及证据。

## 支持范围

- 实施方案编写、修改与检查。
- 项目工作总结或研制工作总结编写、修改与检查。
- 方案与总结的对照检查。
- 融合章节参考、技术编写要点及按项目调整目录。

目前尚不自动承担完整需求规格说明、软件设计说明或技术总结的专项编写。

## 提供的资料

优先提供任务书或合同技术附件、目标与范围、已有基础、指标、工期及交付成果。涉及时补充数据、接口、部署环境和组织安排。明确哪些文件是当前依据，哪些仅是历史样例。

## 文件结构

```text
skills/gis-project-docs/
  SKILL.md
  agents/openai.yaml
  references/
    implementation-guide.md
    summary-guide.md
    project-intake.md
    review-rules.md
docs/
  index.html
  styles.css
  app.js
  downloads/gis-project-docs-v3.zip
```

`docs/` 为 GitHub Pages 静态介绍与下载页面；从 `main` 分支的 `/docs` 发布，无需安装网站构建依赖。

## 验证范围

技能结构和参考链接已检查，规则经场景走查。完整文档生成效果需结合真实任务持续测试。Word 文件输出需另行检查页面版式。

仓库仅包含通用技能规则和展示页面，不包含原始客户资料、模板原件、项目报告或本地临时文件。
