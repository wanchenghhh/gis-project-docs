# 项目资料清单

先从现有资料提取，仅询问影响当前任务的缺项。整理材料无需外部系统连接。

## 通用信息

- 文档用途、受众、类型与项目阶段。
- 文档用途及希望展开的深度；已有建议目录、客户提交结构或格式要求（有则提供，不要求选择目录模式）。
- 项目名称、建设与承建单位、文档版本、信息截至日期。
- 合同、任务书、确认需求、批准变更，及它们的版本和适用范围。
- 建设目标、业务范围、模块或工作包、成果类型。
- 功能与性能指标及单位、条件和验收依据。

## 实施方案所需

- 已有基础及本次新增、升级边界。
- 已确定技术方案、数据与接口、部署环境；关键业务流程、数据流转、子系统输入输出及技术难点（涉及时提供）。
- 任务安排、负责人或角色、计划时间、依赖和完成标志。
- 质量、测试、评审、配置及变更要求。
- 成果和交付安排、培训及运维承诺依据。

## 总结或对照检查所需

- 实施方案的版本、批准状态与后续计划调整。
- 阶段实际时间、活动、工作产品、评审或测试记录。
- 指标实际结果、测试条件及报告出处。
- 成果名称、版本、数量、交付状态与交付记录。
- 问题整改、遗留事项、变更和验收状态。

仅检查草稿时，不要求完整项目包：先做结构、表述、内部一致性和可见缺项检查；外部真实性和范围完整性依赖额外依据。区分“未提供证据”和“项目未开展该活动”。

## 任务内事实记录

可采用轻量表：字段｜提取值｜来源章节或表格｜计划/实际/要求/建议｜待核实事项。只为当前任务保存，不把项目资料持久写入通用技能。
