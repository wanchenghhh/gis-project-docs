# 文档检查规则

## 检查层次

1. 结构与用途：本次任务的结构约束是否遵守，章节是否适用，摘要是否与正文一致，阶段语气是否正确。
2. 信息完整性：任务是否有实施方法、成果及完成标准；总结是否有实际结果和证据。
3. 内部一致性：名称、日期、版本、数量、单位、角色和承诺是否一致；文字与表格是否对应。
4. 依据与追溯：有项目依据时检查范围、指标、交付成果和批准变更；没有依据时限定检查结论。
5. 引用与版式：可检查文本中的失效引用、题注和编号；页码、分页、表格溢出等需实际渲染后验证。

## 关键检查

- 建设目标与内容能否对应到任务、技术方案、计划和成果。
- 软件设计阶段的完成标志是否指向软件设计成果，而非误复制需求评审；阶段名称、产品和评审一致。
- 日期差异区分计划与实际，不直接认定矛盾；核实是否有批准变更或报告截止日期不同。
- 统计人数、数量时考虑角色兼任和设备分配，不在口径不明时直接判错。
- 功能新增、升级和复用边界是否明确，原项目成果是否混入本次新增成果。
- GIS 数据涉及时核对数据类型、范围、坐标或时空基准、精度/分辨率、更新、质量评价和成果；适用要求来源于当前项目。
- 性能单位、数量、耗时、测试条件及阈值是否一致。毫秒耗时没有处理数量时不足以验证条/秒。
- “全部完成”“全部符合”“通过验收”等结论是否被记录支持；分别检查完成、达标、交付与验收状态。
- 文档清单中版本是否与修改记录及实际交付记录对应；版本差异可能有合理原因，须核实。
- 搜索“错误!未找到引用源。”及同类引用错误；核对正文中的图表指向与可见题注。
- 脱敏造成的名称、空白或缺图单独标记，不推定原文一定有同样问题。不猜测被删除信息。
- 当前标准适用性、批准方案、测试真实性及验收结论不能仅凭历史样例确认。

## 对照检查

建立：要求编号/内容｜方案位置及安排｜总结位置及实际结果｜证据｜差异｜状态。

按工作包建立名称映射，处理简称和更名，无法确认时待核实。检查范围覆盖、时间差异、成果齐套、指标和验证、质量活动、变更与遗留问题。合同追溯表本身也要核对，不能把作者填写的对应关系当作已验证事实。

## 输出问题

字段：位置｜问题｜依据｜影响｜修改建议｜状态。

- 明确错误：文本可直接证明的错误，例如失效引用。
- 疑似不一致：存在差异但可能有口径、版本或阶段原因。
- 资料不足：无法支持或排除某个结论，指出具体所需证据。

按影响排序，先处理范围、指标、事实和结论，再处理表达与格式。没有发现问题时说明检查范围和依据，不出具无依据的“项目全部合格”结论。用户仅要求检查时不修改原件。

## 通用编写方法的补充检查

- 概述和目录说明与最终章节一致，不能保留模板旧章节号或不存在的章节。
- 业务流程中的参与角色、步骤及异常处理与功能一致；数据流程中的来源、流向及存储与接口和数据库描述一致。
- 子系统输入输出名称、格式及发送接收关系相互匹配，输出有可说明的处理来源。
- 技术难点的解决措施回应问题与约束，并有拟定验证方法；不要将尚未验证的方案写成既成效果。
- 技术指标映射到相关模块和验证安排；所谓正偏离或优于要求的承诺必须有本项目依据，不能由模板示例推定。
- 双向追溯检查要求遗漏和无依据的额外承诺，编号引用随最终目录重新建立。
- 签署和修改记录根据真实记录填写，不按模板说明人为统一日期或复制示例人员。
