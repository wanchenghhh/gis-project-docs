01 / 能力范围

从编写到核对，一套工作方法

A / 编写与修改

实施方案与工作总结

整理项目事实，选择适用章节，分章形成正文。区分计划、实际结果、备选建议与待确认事项。

B / 文档检查

给出位置与修改依据

检查指标结论、成果清单、数字、版本和失效引用。缺少证据时列出待核实事项，不擅自判定不合格。

C / 对照检查

要求与成果逐项对应

对照方案和总结，检查范围覆盖、计划差异、交付成果与验证证据，识别遗漏或无依据的承诺。

02 / 章节参考

先看框架，再按项目选章节

参考目录帮助了解文档的内容覆盖。它不是所有项目的固定要求：纯软件、数据建设与复杂集成项目，应有不同的结构。

  1. 背景与任务依据
  2. 目标与建设内容
  3. 功能及性能要求
  4. 总体建设方案
  5. 实施计划
  6. 进度与组织
  7. 质量与过程管理
  8. 交付及后续服务
  9. 要求追溯
按需要展开

数据建设、算法研发、系统集成、部署、硬件采购与试验仅在项目涉及时展开。简单项目可以合并章节。

  1. 范围
  2. 引用文档
  3. 总体设计
  4. 总体技术方案
  5. 技术方案
  6. 关键技术和解决途径
  7. 项目组织实施
  8. 项目质量管理
  9. 集成部署方案（可选）
  10. 验收与交付
  11. 售后服务
  12. 追踪关系
已提炼为写作指南

参考业务与数据流程、接口、子系统输入输出、关键技术和双向追溯。原模板不作为项目事实依据，也不随包发布。

  1. 项目基本情况
  2. 实施或研制完成情况
  3. 要求符合性
  4. 质量及过程管理情况
  5. 主要建设成果
  6. 问题、差异与经验
  7. 下一步安排
结论有证据

每项内容说明原要求、实际完成情况、成果、验证依据和遗留问题。完成测试不自动表示通过最终验收。

03 / 使用方法

提供资料，然后像日常协作一样提问

1. 安装技能

解压，将 gis-project-docs 文件夹放入个人技能目录 ~/.agents/skills/。

2. 提供当前项目资料

任务书或合同附件、建设范围、指标、工期和成果。有多少先提供多少，历史样例注明用途。

3. 调用并审阅

输入 $gis-project-docs 和任务要求。先看目录、再写正文，或直接要求检查已有草稿。

先看项目目录

请使用 $gis-project-docs，根据我提供的项目资料，先给出实施方案建议目录，并说明每章写什么，暂时不要编写正文。

编写完整方案

请使用 $gis-project-docs，根据附件编写实施方案。按项目组织目录；未确定的技术、数量和承诺标为待确认。

检查总结报告

请使用 $gis-project-docs，检查研制工作总结的指标结论、成果清单、前后一致性与引用，输出位置、依据和建议，暂不修改原文。

对照计划与成果

请使用 $gis-project-docs，对照实施方案与总结报告，检查要求覆盖、实际差异、交付成果及验证证据，区分计划与实际日期。

04 / 资料与边界

模板提供方法，项目资料提供事实

优先提供

  • 目标、范围、用户与已有基础
  • 任务书、合同要求、确认需求及变更
  • 功能和性能指标、工期及交付成果
  • 涉及时补充数据、接口、环境和职责

检查结果如何理解

  • 明确错误：文档本身能够证明的问题
  • 疑似不一致：可能存在阶段或统计口径差异
  • 资料不足：需要补充具体证据才能判断
  • 内容检查与 Word 版式检查分别进行

当前已完成技能结构校验和规则场景走查；完整文档生成效果仍需在真实任务中持续验证。
