01 / 陪伴项目的文档工作

始于清晰的计划，
落于有据的成果。

这是一个可安装的 AI 文档技能。把它带到你的日常协作中，从编写实施方案，到检查工作总结，让资料、过程与交付相互对应。

02 / 融合章节参考

一套方法，适应不同项目。

多个素材的经验已融合为通用指南。点击章节，查看写作内容、适用条件和需要准备的资料。

内容覆盖参考 · 不是固定目录
↳

简单项目可以合并章节，复杂项目可以按系统、数据或工作包展开。新增素材会补充方法与检查规则，不会让每个项目的目录越来越长。

03 / 从头到尾的文档支撑

连接计划与交付的每一步。

把“准备做什么”与“实际完成什么”接起来。对关键事实、验证结果与待办事项，始终有迹可循。

01 / START

理清范围

目标、依据、任务与现有基础。

02 / PLAN

形成方案

方法、职责、进度与成果安排。

03 / REVIEW

检查对应

指标、版本、数字与验证依据。

04 / DELIVER

总结成果

完成情况、差异、交付与待办。

04 / 带入你的工作

三步开始，一起把文档做好。

网站提供介绍、章节参考与技能下载。编写和检查在你安装技能后的 AI 对话中进行。

1

安装技能

解压，把 gis-project-docs 放入 ~/.agents/skills/。

2

提供资料

先提供项目依据、范围、指标、工期和成果，历史素材注明参考用途。

3

提出任务

调用 $gis-project-docs，先看目录、直接编写，或核对已有草稿。

先看目录

请使用 $gis-project-docs，根据项目资料先给出实施方案建议目录，说明每章写什么，暂不编写正文。

编写方案

请使用 $gis-project-docs，根据附件编写实施方案，按项目组织章节，未确定的技术、数量和承诺标为待确认。

检查总结

请使用 $gis-project-docs，检查工作总结的指标结论、成果清单、前后一致性与引用，输出位置、依据和建议，暂不修改原文。

对照检查

请使用 $gis-project-docs，对照实施方案与工作总结，检查要求覆盖、计划差异、交付成果及证据，区分计划与实际。
